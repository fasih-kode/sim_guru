## HOTFIX-F1-NGROK-CSRF-01 — login HTTPS melalui reverse proxy lokal — 28 Oktober 2026

Diagnosis: mode development sebelumnya selalu menandai request sebagai HTTP polos untuk Gorilla CSRF. Selain itu, `CrossOriginProtection` membandingkan host publik Origin dengan host upstream sebelum ada normalisasi proxy. Browser HTTPS lewat ngrok karena itu dapat menerima GET tetapi POST login ditolak 403.

Perbaikan memakai `APP_TRUSTED_PROXY_CIDRS` yang kosong secara default. Hanya peer dalam CIDR yang dikonfigurasi boleh menyampaikan satu `X-Forwarded-Proto: https` dan host eksternal tunggal yang valid. Host dinormalisasi sebelum pemeriksaan cross-origin, header forwarded dibuang sebelum mencapai handler, dan CSRF tetap diwajibkan. Middleware CSRF HTTP dan HTTPS berbagi key; cookie sesi serta CSRF mengikuti keamanan request yang sudah diverifikasi. Header proxy dari peer yang tidak dipercaya tidak mengaktifkan HTTPS.

Tes integrasi `TestHTTPSReverseProxyLoginCSRFIntegration` memakai akun sintetis di database `_test`: login HTTP lokal, login TLS melalui reverse proxy loopback, cookie Secure pada alur HTTPS, akses `/kehadiran-saya`, token hilang/salah, Origin palsu, logout/password/presensi tanpa CSRF, dan spoof header dari peer di luar CIDR. Tidak ada capture/presensi yang dilakukan. Konfigurasi lokal untuk proxy satu mesin dicatat di `docs/DEVELOPMENT.md`; jangan mempercayai seluruh domain ngrok atau CIDR publik. Uji HTTPS dilakukan dengan reverse proxy sintetis; smoke test langsung ke tunnel ngrok belum menjadi bukti dari tes ini.
